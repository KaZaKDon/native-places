# Native Places Admin

Административная панель Native Places — отдельное React + Vite приложение для администраторов и модераторов.

## Назначение

Админка используется для:

- модерации объявлений, отзывов и жалоб;
- обработки обращений;
- просмотра и управления пользователями;
- управления категориями, типами объектов и характеристиками;
- управления справочниками и настройками;
- работы с тарифами и платежами;
- создания и обработки рассылок;
- просмотра статистики и журналов модерации;
- управления кодами доступа модераторов.

## Структура

```text
admin/src/app/          маршрутизация
admin/src/pages/        страницы разделов
admin/src/components/   общие компоненты
admin/src/layouts/      каркас админки
admin/src/context/      состояние авторизации
admin/src/shared/api/   клиентские API-модули
admin/src/config/       роли, навигация и настройки
admin/src/styles/       общие темы и переменные
admin/public/           статические файлы
admin/dist/             результат production-сборки
```

Точные копии PHP-файлов admin API находятся в:

```text
docs/backend/admin/**
```

## Роли

- `admin` — полный административный доступ;
- `moderator` — доступ только к разрешённым разделам модерации.

Ограничения интерфейса не заменяют серверную проверку роли. Каждый защищённый PHP endpoint обязан самостоятельно проверять административную сессию и разрешённую роль.

## Локальный запуск

```bash
cd admin
npm ci
npm run dev
```

Vite проксирует `/api` на `https://native-places.ru`. Для другого API можно задать `VITE_API_BASE_URL` при запуске или сборке.

## Проверка и сборка

```bash
npm run lint
npm run build
```

Production-сборка создаётся в `admin/dist/` и рассчитана на публикацию по пути `/admin/`.

## Правила разработки

1. API-вызовы размещаются в `admin/src/shared/api/`.
2. Доступ к странице задаётся в `admin/src/app/App.jsx` и проверяется через `RequireRole`.
3. Нельзя считать скрытую кнопку достаточной защитой: доступ проверяет PHP backend.
4. Изменение admin API сначала готовится по точной копии из `docs/backend/admin`, затем переносится на хост и повторно фиксируется в документации.
5. Ошибки PHP, SQL, пути и секреты не выводятся пользователю админки.
6. Рассылки не запускаются без проверки типа письма, основания отправки и списка отписавшихся пользователей.
