# Native Places — SEO-аудит и патч 1.0

Дата: **15 ноября 2026 года**. Исходники: `native-places-main (1).zip`.
Продакшен: https://native-places.ru/ (проверка доступности по публичному HTML).

## Подтверждённое на опубликованном сайте

- Корневая страница, `/categories`, `/map`, все шесть `/category/*` и опубликованная карточка `/place/place_e4dec6d738bae71c` отдают роботам осмысленный серверный HTML.
- Категории недвижимости, баз отдыха, охоты, природы и др. содержат очень мало или не содержат опубликованных объектов; видна карточка аренды в Новочеркасске.
- Точный статус Google/Yandex индексации без доступа к панелям вебмастера неизвестен. Поисковый поиск не показал органические результаты по данному домену, но это не количественный отчёт об индексации.
- URL robots.txt и sitemap.xml были недоступны для просмотра через инструмент веб-просмотра; это **не доказательство** ошибок HTTP. Их нужно проверить после загрузки напрямую и в вебмастерах.

## Обнаруженные технические проблемы до патча

1. Неунифицированные `robots.txt` (в корне и `public/`), включая запрет URL, на которых настроен `noindex`.
2. В `.htaccess` нет явного правила приведения `www` и HTTP к `https://native-places.ru` (возможные дубли).
3. Заголовок и description серверных PHP-страниц расходятся с React SEO и HTML fallback.
4. При отказе БД в категории PHP ошибочно мог возвращать пустую страницу с HTTP 200, что создаёт ложное сообщение о пустом каталоге.
5. Главная React показывает только hero; ссылки на все шесть категорий отсутствовали в видимом основном содержимом.
6. Динамические карточки не используют населённый пункт в SEO title/description, хотя в БД есть соответствующие поля.
7. Структурированные данные Place присваивали дефолтное изображение чужой карточке, а Open Graph type для карточки был `article` (скорректировано).

## Что изменено в патче

- Единый robots.txt и sitemap в нём; noindex-страницы открыты для чтения meta robots.
- Добавлен постоянный редирект с `www` и с HTTP на основной HTTPS-домен (с учётом `X-Forwarded-Proto`).
- Согласованы title и description всех индексируемых статических/категорийных страниц в React и PHP.
- Серверные категории теперь выводят H1, вводный текст и описание раздела, совпадающие по смыслу и формулировкам с видимым React-содержимым.
- Добавлен видимый раздел главной с шестью внутренними ссылками на категории; серверный HTML содержит тот же раздел и отражает текущую географию.
- Для опубликованных карточек заголовки и описания получают региональный контекст из фактических данных места.
- Ошибка БД при построении категории теперь возвращает HTTP 503 + `noindex`.
- Обновлены даты *действительно изменённых* статических разделов в sitemap (с 2026-08-10 на 2026-11-15).
- Добавлены regression-тесты и production smoke-проверки.

## Важные ограничения

- Изменения **не загружены** на хостинг автоматически. Необходимо развернуть оба слоя (frontend и PHP).
- Продакшен MySQL, хостинговый .htaccess и доступ к Google Search Console / Яндекс Вебмастеру здесь недоступны. Итоговый live HTTP status, реальную генерацию sitemap и редиректы проверять после развёртывания.
- Нельзя обещать поисковый трафик после одной технической настройки. Основной следующий этап — наполнение уникальными объектами, отзывами/практическими данными и качественными фотографиями.
- Публичные карточки, снятые с публикации или истёкшие, не должны оставаться в sitemap; существующая SQL-фильтрация сохранена.
- Никакие API-ключи, реальные файлы конфигурации БД и платёжные секреты в патч не входят.

## Порядок развёртывания

1. Сохранить резервные копии файлов на хосте и исходников проекта.
2. Накатить `NativePlaces_SEO_SOURCE_PATCH.zip` поверх корня проекта с папками `src/`, `docs/`, `public/` и файлом `package.json` (только изменённые файлы).
3. Выполнить в **локальном проекте** `npm ci`, `npm test`, `npm run lint`, `npm run build`. Файлы `dist/` в исходный SEO-патч не включены.
4. Загрузить содержимое `dist/` в корень публичного сайта, сохранив директории `/api`, `/admin`, `/uploads` и серверные PHP-файлы. Не удалять старую базу или API.
5. Распаковать `NativePlaces_SEO_HOST_PATCH.zip` **в корень сайта**, где размещены `index.html`, `api/` и `sitemap.php`. В пакет включены `.htaccess`, `robots.txt`, `seo-router.php` и `seo/{config,helpers,data,snapshots}.php`. Перезаписать нужные файлы после создания резервных копий.
6. Убедиться, что фактический хостинг использует Apache с `.htaccess` и что PHP 8.2 с расширениями PDO/MySQL и mbstring доступен. При Nginx правила редиректа и маршрутизации требуют конфигурации Nginx.
7. Проверить вручную: `/`, `/categories`, `/category/rent`, `/place/place_e4dec6d738bae71c`, `/map`, `/robots.txt`, `/sitemap.xml`, `/account` и несуществующий адрес. В sitemap должны присутствовать только **опубликованные** карточки.
8. Убедиться, что `https://www.native-places.ru/` возвращает 301 на `https://native-places.ru/` (без цепочек и циклов). Проверить HTTP→HTTPS.
9. Добавить сайт в Яндекс Вебмастер и Google Search Console (при отсутствии), подтвердить владение, отправить `https://native-places.ru/sitemap.xml`, выполнить проверку URL основных разделов, дождаться результатов индексации.

## Приоритеты наполнения и продвижения (после выкладки)

1. Довести хотя бы одну-две категории до полезного уровня: качественные реальные описания и фотографии, цена/условия, география, контакты, дата актуальности; лучше начать с наиболее представленных направлений по Ростовской области.
2. Не создавать сотни пустых комбинаций «город + категория». Региональные посадочные страницы делать только после реального наполнения и уникального содержания.
3. Добавлять внешние упоминания, ссылки из собственных тематических проектов, профили в релевантных каталогах без закупки спам-ссылок.
4. Проверять «Страницы в поиске», «Исключённые страницы», crawl errors, показы и клики раз в 1–2 недели после регистрации в кабинетах, а не судить по единичным поисковым запросам.
