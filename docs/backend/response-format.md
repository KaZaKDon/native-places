# Общий формат JSON-ответов

Backend API использует единый JSON-формат для успешных и ошибочных ответов.

## Успешный ответ

Базовая форма:

```json
{
  "success": true,
  "data": {}
}
```

Где:

| Поле | Тип | Описание |
|---|---|---|
| `success` | boolean | Всегда `true` для успешного ответа. |
| `data` | object / array / null | Данные ответа. Структура зависит от endpoint-а. |

## Ошибочный ответ

Базовая форма:

```json
{
  "success": false,
  "message": "Текст ошибки",
  "extra": {}
}
```

Где:

| Поле | Тип | Описание |
|---|---|---|
| `success` | boolean | Всегда `false` для ошибки. |
| `message` | string | Человекочитаемое описание ошибки. |
| `extra` | object | Дополнительные данные ошибки, если они есть. |

## HTTP-статусы

Чаще всего используются такие статусы:

| HTTP | Значение |
|---:|---|
| `200` | Успешный запрос. |
| `201` | Успешное создание сущности. |
| `400` | Некорректный запрос или некорректный JSON. |
| `401` | Пользователь не авторизован. |
| `403` | Недостаточно прав. |
| `404` | Сущность не найдена. |
| `405` | Метод запроса не разрешён. |
| `409` | Конфликт данных, например уже существующий email. |
| `422` | Ошибка валидации. |
| `500` | Внутренняя ошибка сервера. |

## Рекомендации для frontend

Frontend должен проверять поле:

```js
response.success
```

Если `success === true`, использовать `response.data`.

Если `success === false`, показывать пользователю `response.message` или обрабатывать ошибку по HTTP-статусу.

## Пример frontend-логики

```ts
if (response.success) {
  return response.data;
}

throw new Error(response.message || 'Ошибка запроса');
```

## Важные замечания

- Даже при HTTP-ошибке backend старается возвращать JSON.
- Текст `message` может использоваться для отображения пользователю.
- Структура `data` описывается отдельно в каждом endpoint-документе.
- Структура `extra` зависит от конкретного endpoint-а и обычно используется для деталей валидации.
