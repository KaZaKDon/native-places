# Native Places Backend — точная копия API с хоста

Дата подтверждения источника: 9 августа 2026 года

Папка `docs/backend` фиксирует PHP backend, который находится на хосте `native-places.ru`. Кодовые блоки в endpoint-документах являются точными копиями файлов с хоста и имеют приоритет над старыми описаниями проекта.

## Главное правило

```text
api/<путь>/<файл>.php
        ↕
docs/backend/<путь>/<файл>.php.md
```

Примеры:

```text
api/auth/login.php
docs/backend/auth/login.php.md

api/places/index.php
docs/backend/places/index.php.md

api/admin/users/show.php
docs/backend/admin/users/show.php.md
```

Имена и вложенность папок повторяют структуру `/api/` на хосте.

## Что является источником истины

Внутри endpoint-документа приоритет имеет:

1. PHP-код, скопированный с хоста.
2. Фактический request/response этого кода.
3. Поясняющий текст, если он проверен по коду.
4. История и старые ссылки на документы — только справочная информация.

До этапа 7.3 инвентаризации поясняющие шапки endpoint-документов могут содержать старые даты, источники или статусы. Это не делает PHP-код неактуальным. Массовое исправление этих шапок выполняется отдельно.

## Специальные документы

Файлы, которые не являются обычными публичными endpoint-вызовами, всё равно остаются в `docs/backend`, если они точно отражают файлы или рабочее состояние хоста. В частности:

```text
docs/backend/seo/sitemap.php.md
docs/backend/admin/plans/paid-test-tariff.md
```

Они не переносятся в backlog и не удаляются во время инвентаризации.

## Правила изменения PHP

1. За основу берётся полный код из соответствующего `.php.md`.
2. Готовится полная новая версия файла, а не отдельный фрагмент без контекста.
3. На хосте создаётся резервная копия заменяемого PHP-файла.
4. Новый файл проверяется через `php -l`.
5. Проверяются метод, авторизация, request, response и ошибки.
6. Проверяется связанный пользовательский или административный сценарий.
7. После успешной проверки код и описание в `.php.md` обновляются до фактического состояния хоста.

Изменение только Markdown без переноса PHP на хост не считается изменением backend.

## Что не делаем

- не восстанавливаем PHP по старым сводным выгрузкам, если есть файл в `docs/backend`;
- не удаляем endpoint только потому, что строка его вызова не найдена во frontend;
- не смешиваем будущий вариант кода с отметкой «на хосте»;
- не помещаем реальные пароли, ключи и секреты в Markdown;
- не объявляем поясняющий текст точным без сверки с PHP-кодом.
