# Авторизация и PHP-сессии

Backend API использует авторизацию на основе PHP session.

## Пользовательская авторизация

Обычный пользователь авторизуется через user session.

После успешного входа backend сохраняет идентификатор пользователя в PHP-сессии:

```php
$_SESSION['user_id']
```

Защищённые пользовательские endpoint-ы используют helper:

```php
requireAuth()
```

## Поведение `requireAuth()`

`requireAuth()` должен:

1. Проверить наличие активной PHP-сессии.
2. Проверить наличие `$_SESSION['user_id']`.
3. Вернуть текущий `user_id`, если пользователь авторизован.
4. Вернуть ошибку `401`, если пользователь не авторизован.

## Endpoint-ы с user session

Примеры разделов, которым обычно нужна user session:

```text
api/my-places/*
api/my-subscription/*
api/profile/*
api/conversations/*
api/messages/*
```

## Админская авторизация

Админская часть использует отдельную session-структуру:

```php
$_SESSION['admin_user']
```

Обычно внутри хранятся данные администратора, включая роль:

```php
role_code
```

## Admin roles

Основные роли:

| Роль | Описание |
|---|---|
| `admin` | Полный доступ к административной части. |
| `moderator` | Ограниченный доступ к административной части. |

## Helper-ы админской авторизации

Для админских endpoint-ов используются helper-функции:

```php
requireAdmin()
requireAdminOrModerator()
```

## `requireAdmin()`

Требует, чтобы текущий admin session пользователь имел роль:

```text
admin
```

Если пользователь не авторизован, endpoint возвращает `401`.

Если пользователь авторизован, но не имеет прав администратора, endpoint возвращает `403`.

## `requireAdminOrModerator()`

Требует, чтобы текущий admin session пользователь имел одну из ролей:

```text
admin
moderator
```

Если пользователь не авторизован, endpoint возвращает `401`.

Если роль не подходит, endpoint возвращает `403`.

## CORS и credentials

Так как авторизация основана на cookie/session, frontend должен отправлять запросы с credentials.

Для `fetch`:

```ts
fetch(url, {
  credentials: 'include'
});
```

Для `axios`:

```ts
axios.create({
  withCredentials: true
});
```

## Рекомендации для frontend

Frontend должен отдельно обрабатывать:

| HTTP | Что делать |
|---:|---|
| `401` | Считать пользователя неавторизованным, перенаправить на login или показать форму входа. |
| `403` | Показать сообщение о недостатке прав. |
| `200` | Обновить состояние авторизации или продолжить сценарий. |

## Проверка текущей сессии

Для пользовательской части обычно используется endpoint:

```text
api/auth/me.php
```

Для админской части обычно используется endpoint:

```text
api/admin/auth/me.php
```

Эти endpoint-ы нужны frontend-приложению для восстановления состояния авторизации после перезагрузки страницы.

## Важные замечания

- User session и admin session нужно рассматривать отдельно.
- Пользовательский login не должен автоматически означать admin login.
- Admin session должна проверять роль.
- Для защищённых запросов frontend должен отправлять cookies.
- При logout backend должен очищать соответствующую session-переменную.
