# Native Places Admin Backend — точная копия API с хоста

Дата подтверждения источника: 9 августа 2026 года

Папка `docs/backend/admin` повторяет структуру `/api/admin/` на хосте. Кодовые блоки в `.php.md` являются точными копиями PHP-файлов с хоста.

## Назначение

Admin API обеспечивает:

- отдельную административную авторизацию;
- ролевой доступ администратора и модератора;
- модерацию объявлений, отзывов и жалоб;
- обработку обращений;
- управление пользователями;
- управление категориями, типами объектов, характеристиками и справочниками;
- работу с тарифами и платежами;
- рассылки;
- статистику и журналирование действий;
- настройки сайта и коды доступа.

## Авторизация

Admin API использует отдельную административную сессию. В точных PHP-копиях применяются helper-функции:

```php
requireAdmin();
requireAdminOrModerator();
```

Они определены в:

```text
api/admin/shared/require-admin.php
docs/backend/admin/shared/require-admin.php.md
```

Ограничение маршрута в React-админке не заменяет серверную проверку роли.

## Роли

| Роль | Доступ |
|---|---|
| `admin` | полный административный доступ |
| `moderator` | только разрешённые операции модерации |

Фактическое разрешение конкретного endpoint определяется его PHP-кодом, а не этой сводной таблицей.

## Связь с React-админкой

Клиентские вызовы находятся в:

```text
admin/src/shared/api/
```

Маршруты и ограничения интерфейса:

```text
admin/src/app/App.jsx
admin/src/config/navigation.js
```

При изменении контракта PHP необходимо одновременно проверить соответствующий API-модуль и страницу админки.

## Правило изменения

1. Найти полный PHP-код в соответствующем `.php.md`.
2. Подготовить полную обновлённую версию файла.
3. Сделать резервную копию на хосте.
4. Перенести изменение и выполнить `php -l`.
5. Проверить доступ `admin/moderator` и фактический request/response.
6. Проверить страницу React-админки.
7. Обновить `.php.md` только до реально развернутого состояния.

## Текущая контрольная точка
