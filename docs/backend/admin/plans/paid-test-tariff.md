# Тестовый платный тариф для проверки кассы

## Назначение

Этот файл нужен, чтобы перед проверкой Ю-Кассы быстро создать один безопасный платный тариф.

Тариф специально маленький:

- `code`: `paid_test_30`;
- цена: `100.00 ₽`;
- лимит: `1` объявление;
- срок: `30` дней;
- статус: активный.

Такой тариф удобно использовать для первого теста оплаты: пользователь выбирает его при создании объявления, backend создаёт запись в `payments`, frontend вызывает `api/payments/create.php` и уводит пользователя на страницу оплаты Ю-Кассы.

## Вариант 1 — через админку

1. Откройте раздел `Тарифы`.
2. Нажмите `Заполнить тестовый платный`.
3. Проверьте поля.
4. Нажмите `Добавить тариф`.

Админка отправит обычный запрос в:

```http
POST /api/admin/plans/create.php
```

## Вариант 2 — напрямую через SQL

Если быстрее добавить тариф через phpMyAdmin, выполните SQL ниже.

```sql
INSERT INTO plans (
    code,
    title,
    description,
    max_places,
    duration_days,
    price,
    is_active,
    created_at,
    updated_at
) VALUES (
    'paid_test_30',
    'Тестовый платный',
    'Тестовый тариф для проверки оплаты через Ю-Кассу: 1 объявление на 30 дней.',
    1,
    30,
    100.00,
    1,
    NOW(),
    NOW()
)
ON DUPLICATE KEY UPDATE
    title = VALUES(title),
    description = VALUES(description),
    max_places = VALUES(max_places),
    duration_days = VALUES(duration_days),
    price = VALUES(price),
    is_active = VALUES(is_active),
    updated_at = NOW();
```

## Проверка после создания

Публичный endpoint тарифов должен вернуть новый тариф:

```http
GET /api/plans/index.php
```

В ответе среди `plans[]` должна быть запись:

```json
{
  "code": "paid_test_30",
  "title": "Тестовый платный",
  "max_places": 1,
  "duration_days": 30,
  "price": 100,
  "is_active": 1
}
```

## Что должно произойти при тесте оплаты

1. Пользователь авторизован.
2. Пользователь создаёт объявление и выбирает тариф `Тестовый платный`.
3. `api/my-places/create.php` создаёт объявление и локальный платёж со статусом `pending`.
4. Frontend вызывает `api/payments/create.php` с `payment_id`.
5. Backend создаёт платёж в Ю-Кассе и возвращает `confirmation_url`.
6. Frontend переводит пользователя на оплату.
7. После оплаты webhook/проверка статуса должны перевести платёж в `paid`, а подписку/объявление — в рабочее состояние согласно текущей backend-логике.

## Перед проверкой кассы

На хосте должны быть настроены переменные:

| Переменная | Для чего нужна |
|---|---|
| `YOOKASSA_SHOP_ID` | ID магазина Ю-Кассы |
| `YOOKASSA_SECRET_KEY` | секретный ключ Ю-Кассы |
| `YOOKASSA_RETURN_URL` | куда вернуть пользователя после оплаты |

Если `YOOKASSA_SHOP_ID` или `YOOKASSA_SECRET_KEY` не заданы, `api/payments/create.php` вернёт `503` с сообщением `Ю-Касса ещё не настроена`.
