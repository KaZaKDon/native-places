# Native Places — текущее состояние

Дата актуализации: 9 августа 2026 года  
Статус: инвентаризация документации, этап 0

## 1. Продукт

Native Places — информационная площадка, каталог и карта мест, объектов и пользовательских маршрутов. Платформа не должна считаться продавцом, арендодателем, туроператором или стороной сделки между пользователями.

На текущем этапе бесплатные тарифы могут использоваться в рабочем режиме. Реальные платные услуги не запускаются до открытия ИП/ООО, утверждения оферты, подключения платёжного провайдера, ККТ/ОФД и проверки юристом.

## 2. Техническая основа

### Публичный frontend

- React 19;
- Vite 8;
- React Router;
- Leaflet и React Leaflet;
- клиентский API через `/api`;
- PHP session cookie с `credentials: include`.

Основные пользовательские сценарии:

- просмотр главной, категорий, карты и карточек мест;
- регистрация и вход;
- профиль и личный кабинет;
- добавление и редактирование объектов;
- избранное;
- отзывы, жалобы и обращения;
- сообщения;
- пользовательские маршруты;
- тарифы, подписки и заготовка платёжного сценария.

### Админка

Отдельное React + Vite приложение по пути `/admin/`. Реализованы разделы пользователей, объявлений, жалоб, отзывов, обращений, категорий, типов объектов, характеристик, справочников, тарифов, платежей, рассылок, статистики, логов и настроек.

### Backend

- PHP 8.2;
- MySQL/MariaDB;
- PHP sessions;
- production API на `native-places.ru`.

Папка `docs/backend` содержит точные копии файлов с хоста в формате Markdown. Относительный путь документа соответствует пути после `/api/`.

## 4. Документация

За источник истины приняты:

```text
docs/backend/**
docs/legal/**
src/**
admin/src/**
```

Старые июньские сводки и промежуточные выгрузки API не должны использоваться для принятия решений, если они отличаются от актуального кода.

Текущий этап ограничен обновлением корневых и индексных документов. Массовое изменение endpoint-документов отложено до пункта 7.3 инвентаризации.

## 5. Известные расхождения

### Регистрация и email

Frontend уже отправляет признаки принятия условий, обработки персональных данных и рекламной рассылки. Зафиксированный `auth/register.php` требует отдельной доработки, чтобы backend проверял и сохранял конкретные версии согласий.

В frontend присутствуют вызовы подтверждения email и восстановления пароля. Их соответствие точным PHP-файлам хоста будет проверяться отдельно на этапе сверки endpoint-документов.

### Юридические страницы

На сайте сейчас используются три короткие hardcoded-страницы. Сегодня подготовлен полный юридический пакет, но он ещё не подключён к публичному реестру документов сайта.

### Публичные данные объявлений

Нет завершённого механизма отдельного согласия на распространение имени, телефона, email, Telegram, точного адреса и координат конкретного объявления.

### Рассылки

Рассылки технически реализованы, но требуют разделения сервисных и рекламных сообщений, проверки действующего согласия и гарантированной отписки.

### Тарифы и платежи

Backend и интерфейсы содержат тарифы и платёжные endpoint-ы. До реального запуска необходимо добавить режимы `disabled/stub/test/live`, заказ, снимок тарифа и документов, строгую проверку webhook, ККТ, чеки и возвраты.

### SEO

Базовые meta-теги, robots.txt и статический sitemap существуют. Динамические карточки и юридические страницы требуют серверного или пререндеренного HTML, корректных canonical, sitemap и HTTP-кодов.

## 6. Ближайшая контрольная точка

Инвентаризация считается завершённой после того, как:

- индексные документы соответствуют фактическому дереву;
- каждый frontend/admin API-вызов сопоставлен точному PHP-файлу;
- будущие задачи отделены от фактического backend;
- юридический пакет разложен по статусам;
- устаревшие документы больше не конкурируют с источниками истины.

Следующий рабочий этап после инвентаризации — подключение юридического реестра, затем регистрация и журнал согласий.
