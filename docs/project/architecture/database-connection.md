# Подключение к базе данных

Backend API использует подключение к MySQL/MariaDB через PDO.

## Назначение

Общий файл подключения к базе данных используется всеми PHP endpoint-ами, которым нужен доступ к данным проекта:

```php
require_once __DIR__ . '/../config/database.php';
```

или из вложенных директорий:

```php
require_once __DIR__ . '/../../config/database.php';
```

## Основная функция

Ожидаемая функция подключения:

```php
getDatabaseConnection()
```

Функция возвращает объект:

```php
PDO
```

## Рекомендуемые настройки PDO

```php
PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION
PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC
PDO::ATTR_EMULATE_PREPARES => false
```

## Charset

Для проекта используется:

```text
utf8mb4
```

Это важно для корректной работы:

- русского текста;
- emoji;
- пользовательских описаний;
- названий мест;
- сообщений;
- комментариев;
- адресов.

## Работа с запросами

Для пользовательского ввода должны использоваться prepared statements.

Пример:

```php
$stmt = $pdo->prepare("
    SELECT *
    FROM users
    WHERE id = :user_id
    LIMIT 1
");

$stmt->execute([
    'user_id' => $userId,
]);
```

## Что важно для frontend

Frontend напрямую не работает с базой данных, но должен учитывать backend-ограничения:

- если объект не найден, API обычно возвращает `404`;
- если данные не прошли валидацию, API обычно возвращает `422`;
- если произошла ошибка базы или неожиданная ошибка backend-а, API обычно возвращает `500`.

## Типовые таблицы

В разных endpoint-ах используются таблицы:

| Таблица | Назначение |
|---|---|
| `users` | Пользователи. |
| `places` | Объявления/места. |
| `categories` | Категории мест. |
| `place_types` | Типы мест. |
| `localities` | Населённые пункты. |
| `place_images` | Изображения мест. |
| `place_attributes` | Значения атрибутов мест. |
| `attribute_definitions` | Описания дополнительных атрибутов. |
| `plans` | Тарифы. |
| `payments` | Платежи. |
| `routes` | Пользовательские маршруты. |
| `route_places` | Места внутри маршрутов. |
| `conversations` | Диалоги. |
| `messages` | Сообщения. |

## Backend notes

- Пароли к базе не должны храниться в документации.
- Реальные credentials должны находиться на хосте или в конфиге окружения.
- Все SQL-запросы с пользовательскими данными должны использовать параметры.
- Для денежных операций и сложных изменений состояния желательно использовать транзакции.
- В публичных endpoint-ах нельзя отдавать служебные поля без необходимости.
