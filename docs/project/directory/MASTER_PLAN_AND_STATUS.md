# Native Places — единый план и фактический статус проекта

**Версия контрольной записи:** 17.11.2026, после v0.4b.2.  
**Назначение:** обязательная точка правды о том, что уже реализовано, что проверено пользователем, что согласовано и что остаётся в очереди. В новом чате читать этот документ и `HANDOFF.md` **перед** разработкой.  
**Статус:** документация; не меняет код, API, БД и действующий сайт.

## 1. Неизменная концепция

Native Places («Родные места», `https://native-places.ru/`) — сочетание **двух независимых направлений**:

1. **Платные объявления:** сохраняются существующие шесть категорий, существующие `places`, тарифы, платежи, модерация и публичные страницы. Справочник не является «седьмой категорией».
2. **Бесплатный «Справочник мест»:** информационные объекты (реки, водоёмы, природа, заповедники/ООПТ, охотугодья, достопримечательности), их геометрия, виды животных/растений, фотографии и проверенные сведения. Просмотр бесплатный; содержание и отображение управляются БД/админкой. Дополнительные коммерческие объявления связываются с местами **отдельно**, без превращения справочной записи в платное объявление.

На главной — три центрированные кнопки: **«Исследовать карту» золотая, «Категории» тёмная, «Справочник» золотая того же цвета и размера, что первая**. Эта часть уже установлена и проверена на скриншоте.

Архитектура: React/Vite/React Router и Leaflet на клиенте; рабочие PHP API + MySQL/MariaDB на **хостинге**. В локальном `E:\Project\native-places` хранятся исходники фронтенда, проектные документы и **текстовые зеркала** серверных PHP в `docs/backend/`; они не гарантируют точного совпадения с production. Перед серверным патчем **сверять реальный файл на хосте**.

## 5. Правила достоверности

- Географию получать из проверяемых источников; OSM применим для геометрии, **не** доказывает обитание рыбы или право охоты.
- URL источника **всегда необязателен**. Для книги — автор, название, издательство, год/страницы по наличию; для наблюдения — место, примерный период, характер наблюдения; для официального акта — идентифицирующие реквизиты и дата проверки. Не придумывать ссылки.
- Для ООПТ показывать режим посещения только при проверке конкретных нормативных документов. Не принимать факт пересечения двух геометрий за доказательство правового режима.
- Для фото различать собственное фото, разрешение правообладателя, открытые лицензии и созданную **пользователем для проекта** ИИ-иллюстрацию; найденная в поиске картинка — не ИИ-генерация.
- Не распространять черновики через публичный API, карту, SEO и Sitemap; не показывать точные точки уязвимых/охраняемых видов без оснований.
- Для вида не наследовать «встречается во всём Дону» на все участки; каждая привязка требует самостоятельной оценки источника и области действия.
