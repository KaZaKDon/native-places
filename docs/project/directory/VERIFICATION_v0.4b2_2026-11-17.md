## Что НЕ проверено / пока отсутствует

- Анонимный доступ к **конкретному** `media/image.php` (нужно отдельно исключить утечку байтов, а не опираться лишь на защиту `media/index.php`).
- Публикация и снятие с публикации вида/occurrence/медиа — пока **не реализованы**.
- Публичные блоки видов рыб, участков и фото на `/directory/river/don`, отдельные SEO-страницы видов/участков — пока **не реализованы**.
- Нет доказательства, что фото — документальная фотография пойманного окуня: в базе **ИИ-иллюстрация**.
- Обработка EXIF/полнота обезличивания медиаданных не проверялась независимо (успешная загрузка сама по себе недостаточна).
- Миграция хранения `MEDIUMBLOB` за пределы MySQL, роли редактора/модератора, проверка масштабируемости — планы.

## Данные объекта

- Река Дон: публичная `/directory/river/don` работает, геометрия 4 технические линии / 117 точек (лишь район Вёшенской).
- Вёшенский участок: `vyoshenskaya`, `sort_order=10`, черновик с GeoJSON; не публичен.
- Вид: `okun-rechnoy`, `Perca fluviatilis`, черновик.
- Наблюдение: личный многолетний опыт на участке между Вёшенской и Базковской (без точных дат/геометок), источник «Личные наблюдения».
- Медиа: иллюстрация создана инструментом ChatGPT (OpenAI), сохранена в закрытой админской медиатеке, после F5 доступна администратору.

## Связанные технические проблемы, уже исправленные ранее

- SPA-прямой URL `/admin/directory` вызывал 404 — изменены правила маршрутизации.
- Посторонняя физическая папка `/www/native-places.ru/admin/directory/` с `publication.php` вызывала 301 (на HTTP + `/`) и 403; была переименована в `directory_backup_20261116`, после чего сервер отдаёт 200 и F5 работает. Функциональный API находится **в `/api/admin/directory/`**, его папку не перемещать.
- Для источника без веб-ссылки нельзя ставить фиктивное `-`; при пустом URL должны различаться разные офлайн-источники.

## Следующий безопасный шаг

Проверка приватности получения изображения **без сессии**, затем проектирование публикации видов/участков. Перед любыми правками получить актуальные файлы, не менять БД/платежи без необходимости. Поставлять отдельные SOURCE/HOST ZIP с обновлением полного плана.
