# Native Places — v0.4: поля, вкладки и правила админки

**Статус:** техническая спецификация будущих форм. В production v0.3 подтверждены только четыре верхние вкладки, базовая форма объекта, импорт GeoJSON, черновики и публикация. Вложенные экраны v0.4 ниже **ещё не разработаны**.

## 1. Меню и вложенная навигация

```text
Админка → Справочник мест
├── Реки и водоёмы
│   ├── Объекты (реки/озёра; существует базовая форма)
│   ├── Участки рек (выбрать реку → перечень сегментов)
│   └── Виды рыб (единая база, фильтр kind=fish)
├── Природные территории
│   ├── Объекты (леса, природные территории)
│   ├── Заповедники и ООПТ (тип protected_area)
│   └── Флора и фауна (та же directory_species с другим фильтром)
├── Охотничьи угодья
│   ├── Угодья
│   └── Правовой режим и источники
└── Интересные места
    ├── Объекты
    ├── Маршруты (только подтверждённые)
    └── Фотографии

Глобальные внутренние редакторы: Источники; Медиа; История изменений.
```

При открытии объекта внутри формы вкладки: **Основное · Карта и участки · Виды · Фотографии · Источники · Доступ и ограничения (если применимо) · Публикация**. Не показывать вкладки, не подходящие типу. Меню объявлений и `/admin/dictionaries` не менять.

## 2. Базовая карточка объекта — что работает v0.3

| Поле | UI/тип | Обязательное | Правило |
|---|---|---|---|
| Тип `type` | Select | Да | Сейчас 7 типов; `protected_area` только после v0.4c |
| Название `title` | Input | Да | 3–180 символов по текущему PHP |
| Slug `slug` | Input | Да | `^[a-z0-9]+(?:-[a-z0-9]+)*$`, ≤160, глобально уникален |
| Регион `region` | Input | Нет | ≤160 |
| Краткое описание `summary` | Textarea | Для публикации | 40–500 символов |
| Подробный текст `body` | Textarea | Для публикации | 120–10 000 символов, отдельно от summary |
| Источник `source_url` | URL | Для публикации | HTTP(S), ≤700 |
| Геометрия `geometry_geojson` | Файл JSON/GeoJSON + карта | Нет для черновика | До 250 КБ, 20 000 точек; тип геометрии зависит от типа объекта |
| Статус | Readonly + действия | Управляется системой | Черновик / опубликован; опубликованный редактировать только после снятия с публикации |

**Предлагаем дополнительно в v0.4:** географические фильтры по региону, набор источников на разных фактах, галерея, предупреждение о непроверенных данных. Не менять задним числом контракт существующей формы без версии API.

## 3. Форма «Участок реки» (v0.4a)

| Поле / control | Обязательно для черновика | Требуется для публикации | Правила |
|---|---|---|---|
| Родительская река | Да | Да | Select только записей `type=river`, immutable при опубликованном участке |
| Название | Да | Да | 3–180 символов |
| Slug участка | Да | Да | латиница/цифры/дефисы; уникален внутри выбранной реки |
| Порядковый номер | Нет | Нет | Числовой порядок в списке, не географическое доказательство |
| Населённый пункт/ориентир | Нет | Нет | Только проверенные названия, не полная локализация без источника |
| Краткое описание | Нет | Да | Предлагаемый минимум 40 символов |
| Подробный текст | Нет | Для отдельной SEO-страницы | Предлагаемый минимум 120 символов, отличающийся от краткого |
| Геометрия GeoJSON | Нет | **Да для отображения на карте** | LineString/MultiLineString; границы должны находиться на проверенном русле |
| Источник геометрии | Нет | Да, если карта опубликована | Ссылка из `directory_sources`, дата проверки |
| Фотографии | Нет | Нет | Только файлы с правом использования |
| Виды рыб участка | Нет | Нет | Выбирать лишь подтверждённые occurrences с источником |
| Статус/публикация | Управляется | Да | Опубликовать можно только при опубликованном родителе; скрытие родителя скрывает участок |

**Ключевое:** существующие у Дона 4 геометрические линии ≠ 4 именованных участка. Пользователь размечает смысловой участок на проверенной линии; перед сохранением — карта, точки начала/конца, предупреждение о возможном пересечении.

## 4. Форма «Вид рыбы / другой биологический вид» (v0.4b)

| Поле | Черновик | Для публикации |
|---|---|---|
| Группа (рыба, птица, млекопитающее, растение, прочее) | Да | Да |
| Русское название | Да | Да |
| Slug | Да | Да |
| Научное название | Если известно | Желательно, с проверкой |
| Краткое описание/признаки | Нет | Да, содержательное |
| Подробные сведения | Нет | Для собственной SEO-страницы |
| Основная фотография | Нет | **Рекомендуется**, но отсутствие фото не основание публиковать чужое без прав |
| Источник описания | Нет | Да |
| Фото: автор, лицензия/разрешение, URL и подпись | Для каждого фото | Да до его публикации |
| Статус | Черновик | Публикация только после проверки |

Кнопка **«Привязать вид»** открывает отдельную форму связи: вид → река/территория → *необязательный* конкретный участок → источник наличия → дата проверки → степень подтверждения → заметка. Не ставить все виды реки автоматически на все участки. Никаких точных мест редких или охраняемых видов без оценки риска.

## 5. Фото и медиатека (v0.4b)

Управление из объекта/вида/участка: `Загрузить` → проверка формата/размера/MIME → метаданные → `Подтвердить права` → preview → `Прикрепить` → `Одобрить`.

Поля: файл, название/подпись, alt (описание изображения), автор, тип лицензии/основание использования, ссылка на лицензию, ссылка на оригинал, текст атрибуции, дата загрузки, основное изображение (только одно на объект), порядок. Администратор должен видеть права **до** публикации. Первоначально только администраторская загрузка; пользовательские фото — отдельная стадия модерации.

## 6. «Заповедник / ООПТ» (v0.4c)

**Базовые поля объекта** (название, slug, регион, описание, GeoJSON) + специальные:

| Поле | Форма | Публикация/смысл |
|---|---|---|
| Вид ООПТ | Select | Заповедник, заказник, национальный/природный парк, памятник природы и др. по официальной категории |
| Официальное название | Input | Обязательно |
| Номер реестра / акта | Input | Если есть; не выдумывать |
| Орган, управляющий территорией | Input | По официальному источнику |
| Основание / ссылка на документ | URL | Требуется для подтверждения статуса |
| Официальный источник границ | URL / reference | Обязателен **для отображения полигона** |
| GeoJSON-граница | Файл + превью | Отсутствие точного полигона не мешает информационной карточке без геометрии |
| Посещение и ограничения | Textarea | Проверенное описание, никаких автоматических утверждений «вход разрешён» |
| Источник режима посещения | URL / reference | Нужен для публичных правовых сведений |
| Дата проверки режима | Date | Показывать пользователю; перепроверять при изменениях |
| Животные, растения и фотографии | Связанные записи | Только подтверждённые связи и легальные фото |

Фиолетовый `#8B5CF6` на карте отличает ООПТ от обычной природы и охотугодий. Сам цвет **не означает запрет входа**. Границы из официальных источников; режим — на отдельной вкладке.

## 7. Охотничьи угодья, природные объекты и интересные места

- **Угодья:** название, регион, организатор/ответственный (при наличии), граница GeoJSON, правовое основание, источник/дата актуальности и ограничения; не обещать право охоты.
- **Природные места:** тип, описание, проверенная геометрия, особенности, источники, фото; маршрут и доступ только при подтверждении.
- **Интересные места:** категория, точка или проверенный маршрут, история/значение, условия посещения, источник, галерея.

Все эти формы используют **один базовый объект** `directory_entries` и типоспецифичные поля (при необходимости новые таблицы), а не копии основной записи на каждый подтип.

## 8. Пользовательские состояния, права, публикация

- Роли: в текущей v0.3 доступ **только администратору** (`requireAdmin()`). Разделение «редактор/модератор» — последующее отдельное решение, не заявлять как реализованное.
- Сохранение: `Сохранить черновик` отдельно от `Опубликовать`; подтверждение для публикации и снятия; повторное открытие после F5.
- Перед публикацией: проверка полноты, лицензий на медиа, доказательств геометрии/видов/режима, уникальности SEO-текстов, корректности ссылок.
- Без доказательств: публиковать базовую карточку без конкретного сомнительного факта/линии; не публиковать вымышленные границы и способы доступа.
- Публикация дочернего объекта запрещена, если родитель не опубликован; снятие родителя мгновенно скрывает дочерние страницы, виды и геометрию из публичного API/Sitemap.
- Изменение опубликованного: сначала снять с публикации по текущей модели, отредактировать и повторно опубликовать. Будущий режим черновых ревизий — отдельная задача.
- Удаление: безопасная архивация предпочтительнее физического `DELETE` после публикации; дизайн статуса `archived` — отдельное согласование.
- В админке показывать `Последняя проверка`, `Источник` и `Доступность для SEO` на каждой сущности.
