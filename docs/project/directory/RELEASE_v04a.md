# Native Places — v0.4a: именованные участки рек (код подготовлен)

**Дата:** 16.11.2026  
**Статус:** ZIP собраны, в production **НЕ установлено**. Production остаётся v0.3.

## Изменения

- Вкладка `Админка → Справочник мест → Реки и водоёмы → Участки рек`.
- Выбор существующей записи `directory_entries.type=river` — допускается и черновик реки.
- Создание и редактирование **черновиков** участков: название, slug (уникален внутри реки), ориентир, порядок, краткий/подробный текст, GeoJSON LineString/MultiLineString, источник.
- Проверка GeoJSON и его визуальный просмотр: переиспользуется действующий GeoJsonEditor, никаких новых npm-зависимостей.
- Реестр источников `directory_sources`: название, тип, издатель, URL, дата проверки, дата публикации, лицензия/URL и комментарий. Источник можно создать в форме участка.
- Серверный admin-only API требует `requireAdmin()` и `directoryAssertCsrf()` и не меняет основное русло Дона.
- Миграция добавляет только `directory_sources` и `directory_segments`, с FK и индексами. `places`, `payments`, `directory_entries`, `directory_entry_events` не изменяются.
- Аудит действий `segment_create` / `segment_update` записывается в существующую `directory_entry_events` по родительской реке. История добавления источника пока не аудитируется отдельно; добавить на следующем этапе.

## Важно: отсутствующие функции

- **Публикация участков отключена** на сервере и в админке до появления публичного API, SEO и страницы участка (план v0.4d). `status='draft'` при каждом сохранении.
- Участки **не появляются** на общей карте, в публичном API или Sitemap. На карте по-прежнему один опубликованный Дон из v0.3.
- **4 OSM-линии / 117 точек** существующего Дона не превращаются автоматически в участки.
- Фактическое совпадение границ участка с руслом пока требует проверки человеком: API проверяет структуру и допустимые координаты GeoJSON, **не** выполняет геопространственное сравнение с линией Дона.
- Нет удаления: по требованиям сохранности и FK пока только редактирование черновиков.
- Фотографии рыб, ООПТ и новые SEO-страницы ещё не реализованы.

## Риски и ограничения

- Сверить фактическую `SHOW CREATE TABLE directory_entries` и движок БД **перед** SQL.
- Новые API работают только после миграции; сначала SQL+PHP и тест без авторизации, затем новая админская сборка.
- Серверные файлы нельзя заменять «папкой api» целиком; только новые пути из серверного архива.
- Данные не публиковать до появления соответствующей публичной реализации.

## Проверки после установки

1. В phpMyAdmin подтверждено наличие обеих новых таблиц и FK.
2. `GET /api/admin/directory/segments/index.php?river_entry_id=1` без сессии → `401` JSON (или действующая политика `403`).
3. `GET /api/admin/directory/sources/index.php` без сессии → `401` JSON.
4. Сборка админки проходит; вкладка «Участки рек» открывается.
5. Сохраняем черновик участка **без GeoJSON**, F5, повторное открытие.
6. Импортируем **проверенную линию участка** и выбираем источник → сохраняем, F5, проверяем линию.
7. Существующая страница Дона, платные объявления, `/map`, `/directory`, Sitemap остаются неизменными.
