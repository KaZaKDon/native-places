# Технический проект — «Справочник мест» (проект, не реализация)

Дата: 15.11.2026.

## Подтверждённая исходная база

Из архива `native-places-main (1).zip`:

- Публичное приложение — React/Vite/React Router (`src/app/router.jsx`).
- Карта — React Leaflet; существующий `src/widgets/MapView/MapView.jsx` выводит маркеры объявлений из `places`. Слоя линий/полигонов для справочника пока нет.
- Админка — отдельный React-клиент, навигация в `admin/src/config/navigation.js`, маршруты в `admin/src/app/App.jsx`.
- `admin/src/data/dictionaries.js` содержит **демонстрационные** виды рыбы и дичи, помеченные «В разработке». `admin/src/pages/Dictionaries/DictionariesPage.jsx` работает с API групп/значений. Это не база проверенных встреч видов в конкретных водоёмах.
- В архиве документируются PHP endpoint-ы в `docs/backend/**`; исходные рабочие PHP-файлы на хосте нужно получить/сверить отдельно, перед внедрением миграций.

## 1. Отдельный bounded context

Предлагаемый модуль `directory` не должен наследовать статус платного объявления, тариф или payment ID.

```
DirectoryEntry (справочный объект)
  ├─ DirectoryGeometry (одна или несколько геометрий/участков)
  ├─ DirectoryMedia (фото и авторство)
  ├─ DirectorySource (источник и дата сверки)
  ├─ DirectorySpecies (связь с видами рыб/животных)
  └─ DirectoryPlaceLink (связь с существующими объявлениями)
```

Пример полей `DirectoryEntry` для проектирования: `id`, `slug`, `title`, `entry_type`, `region_id`, `locality_id?`, `summary`, `body`, `status` (`draft/review/published/archived`), `updated_at`, `published_at`, `seo_title`, `seo_description`. Проверить реальную схему БД и соглашения о названиях до миграции. Не вводить дубли регионов или таксономий, если они уже есть.

## 2. Географическая модель

- Поставщик геометрий — OpenStreetMap **при соблюдении лицензии ODbL и требований атрибуции** или другой правомерный геодатасет. Не извлекать геометрию путём массового парсинга растровых тайлов.
- Координаты: WGS 84, долгота/широта в GeoJSON (`[lon, lat]`), в Leaflet преобразовывать в `[lat, lon]`.
- `Point` — родник, памятник, смотровая точка.
- `LineString/MultiLineString` — русло реки, протяжённый маршрут/участок.
- `Polygon/MultiPolygon` — озеро, природная территория, охотничье угодье **только при наличии достоверных границ**.
- Для Дона не загружать всю детальную геометрию от истока до устья на каждом масштабе. Хранить участки/контуры, bounding box, упрощённые геометрии под масштаб, по возможности загружать по `bbox` и `zoom`.
- Если геометрия не подтверждена, разрешить карточку без геослоя или ограничиться достоверной точкой. Не создавать вымышленные границы охотничьих угодий.
- Для охотугодий необходимо отдельно проверить актуальность и правомерность границ; сведения о границах не означают разрешения на охоту.

## 3. API и админка (предварительный контракт)

Публичный API, только опубликованные данные:

- `GET /api/directory/index.php?type=river&region=...&page=...`
- `GET /api/directory/show.php?slug=...`
- `GET /api/directory/geometry.php?bbox=...&zoom=...&type=...`

Административный API — только по ролям и с серверной валидацией:

- `GET /api/admin/directory/index.php`
- `POST /api/admin/directory/create.php`
- `POST /api/admin/directory/update.php`
- `POST /api/admin/directory/publish.php`
- `POST /api/admin/directory/archive.php`

Эти адреса **предлагаемые**, ещё не реализованы; сверить с реальным PHP API, CSRF/session-политикой и существующими соглашениями. Для загрузки геометрии отдельно ограничить размер, валидировать тип GeoJSON, координаты и допуски; для записей — уникальность slug и аудит изменений.

### Предполагаемое расположение frontend

```
src/features/directory/       модель/хуки/API и компоненты справочника
src/pages/DirectoryPage.jsx   публичный список и фильтры

admin/src/pages/Directory/    интерфейс управления, вкладки
admin/src/shared/api/directoryApi.js
```

Не смешивать CSS всех модулей: использовать существующие централизованные токены и локальные стили.

## 4. Интеграция карты

В `MapView` добавить **независимый** слой `DirectoryMapLayer` (через `GeoJSON`, `Polyline`, `Polygon`, `Marker` из React Leaflet) и загрузчик видимой области; существующую отрисовку объявлений не менять без необходимости.

В UI переключатели:

- `[✓] Справочник` — географические данные (линии/области/точки).
- `[✓] Объявления` — нынешние маркеры.

По клику на геометрию открывать компактную карточку-предпросмотр с ссылкой на `/directory/:type/:slug` (структуру URL окончательно уточнить перед подключением SEO). При конфликте полигонов и маркеров установить явный порядок слоёв и hit testing.

## 5. Публичные страницы и SEO

- Основная страница `/directory` — с доступным роботам серверным HTML и реальными ссылками на опубликованные объекты.
- Пример карточки: `/directory/river/don-rostov` (это пример, не опубликованный URL).
- Уникальные title/description/H1, self canonical, BreadcrumbList; применять подходящую Schema.org разметку и не обещать свойства, которых в записи нет.
- На сервере — `200` для опубликованного, `404` для отсутствующего, `noindex` для черновиков/служебных страниц; в sitemap **только** опубликованные записи.
- Полезные источники и авторство фото; реальные местные сведения. Не генерировать массово пустые страницы «река + рыба + район».
- Отображаемый React-контент и серверный SEO-snapshot должны соответствовать **одним и тем же данным** из базы.
- Не заменять текущие категории объявлений и не ломать уже работающие 9 основных SEO-страниц/существующие карточки.

## 6. Права и экономическая модель

- Чтение опубликованной справочной информации — бесплатно и без входа.
- Модерация/редактирование — разрешённые роли; роль и разрешения проверяются на PHP backend.
- Платёжный сценарий объявлений работает **отдельно**. Новый справочник не добавляет платную категорию и не связывается с тарифом.
- Возможные пользовательские предложения — отдельный будущий workflow с проверкой, не прямая публикация.

Публичный API, опубликованные страницы и геослой остаются проектом следующего этапа. Существующие PHP helper-файлы не перезаписываются.

## Реализация v0.2 — геометрия в админке

Клиентский `admin/src/pages/Directory/geojson.js` принимает GeoJSON Geometry / Feature / FeatureCollection и переводит несколько речных линий в `MultiLineString`. Нормализованная **только** геометрия отправляется существующим методом `POST /api/admin/directory/save.php`. Нет новой таблицы, эндпоинта, изменения тарифов или публичной выдачи.

`GeoJsonEditor.jsx` — загрузка до 250 КБ, сообщения об ошибках и предпросмотр, `GeoPreviewMap.jsx` — лёгкий Web Mercator слой поверх запрашиваемых **только для видимого окна** тайлов OSM. Слой неизменяемый, редактирования картографических координат мышью пока нет. Картографическая система и геометрия отделены от формы/таблицы.

Прямая загрузка геометрии в браузере происходит локально; API не получает исходный файл/FeatureCollection, получает только компактный Geometry JSON. Карта загружает фоновые OSM-тайлы при открытой форме с валидной геометрией. Лицензию и источник проверяет администратор.

## Реализация v0.3 (подготовлено, не установлено)

Фактический SQL остался из v0.1: `directory_entries.status: draft|published`, `published_at`, `directory_entry_events` для аудита. В админке добавлено действие публикации, доступное admin, с CSRF и транзакционным изменением статуса.

Публичный PHP API под `api/directory/`: `index.php` — 24 записи/страница, `show.php` — отдельная опубликованная запись по type+slug, `map.php` — не более 60 опубликованных геометрий. Значение `truncated` в map API сигнализирует, что на карте пока не все объекты. При наполнении справочника потребуется bbox+zoom и пространственный индекс.

Публичный React: `src/pages/DirectoryPage.jsx`, `DirectoryEntryPage.jsx`, `src/features/directory/DirectoryMapGeometry.jsx`, `src/shared/api/directoryApi.js`. Карта на React Leaflet рисует GeoJSON и имеет два независимых слоя. SEO router использует `seo/directory.php` и те же опубликованные таблицы, что и публичный API. Sitemap добавляет `/directory` и карточки только при наличии опубликованных строк.

Чтобы отредактировать опубликованную карточку, администратор снимает её с публикации (published → draft), правит через v0.1 `save.php` и публикует снова. Это намеренная защита на этапе v0.3. Доступные из базы справочные объекты не привязаны к оплатам.
