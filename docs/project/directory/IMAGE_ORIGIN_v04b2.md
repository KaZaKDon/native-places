# Native Places — изображения рыб: происхождение и права (v0.4b.2)

**Дата:** 17.11.2026. **Статус:** патч подготовлен, установка на хостинг и реальная загрузка изображения ещё не проверены.

## Решение

В меню «Справочник мест → Реки и водоёмы → Виды рыб → Открыть вид → Загрузить изображение» предусмотрен обязательный выбор происхождения:

1. **Фотография** — настоящее фото, сделанное администратором или полученное от другого автора. Обязательны имя автора/правообладателя, основание использования (собственное фото, разрешение, открытая лицензия и т. п.) и подтверждение прав; внешние ссылки необязательны, если они отсутствуют.
2. **Иллюстрация, созданная ИИ** — изображение действительно сгенерировано инструментом ИИ. Обязательны название инструмента (по умолчанию `ChatGPT (OpenAI)`) и отдельное подтверждение администратора, что изображение не скопировано из чужого источника и может использоваться на сайте. Поля автора фотографии и сторонней лицензии скрыты и **не обязательны**. Сторонняя лицензия автоматически не выдумывается.

**Важно:** изображение, найденное через поиск или загруженное с чужого сайта, не становится ИИ-генерацией из-за того, что его показал ассистент. Оно должно учитываться как чужая фотография/изображение с правами, соответствующими его источнику. Даже сгенерированный файл может содержать охраняемые элементы; администратор подтверждает право размещения конкретного изображения. ИИ-иллюстрацию запрещено выдавать за документальный снимок рыбного экземпляра или места поимки.

## Хранение без миграции

В `directory_media` уже имеются `author VARCHAR(250) NOT NULL`, `license_name VARCHAR(180) NOT NULL`, `attribution`, `source_url`, `license_url`. Новые поля таблицы не нужны для текущего этапа:

- для фотографии PHP сохраняет вручную введённые `author` и `license_name`;
- для `image_origin=ai_generated` PHP **сам**, не доверяя полям клиента, формирует `author = "ИИ: <название инструмента>"`, `license_name = "ИИ-иллюстрация — отдельная лицензия на чужое фото не требуется"` и атрибуцию с инструментом генерации;
- при выводе в админке запись показывается с явной пометкой «ИИ-иллюстрация», без слова «фотография»;
- существующие записи, если они есть, остаются совместимыми. При отсутствии `image_origin` API использует `photo` — защита старых клиентов.

Это временная модель для админских черновиков. При будущей публичной публикации можно вынести происхождение в самостоятельное структурное поле, но сейчас не вводим миграцию без необходимости.

## Валидация и безопасность

- Для **обоих типов** обязательны файл (JPEG/PNG/WebP, до 3 МБ) и `rights_confirmed=1`.
- Для фотографии обязательны `author` и `license_name`.
- Для ИИ обязательны `ai_tool` (1–190 символов), сервер не доверяет переданным `author`/`license_name`.
- `image_origin` принимает только `photo` и `ai_generated`, иначе HTTP 422.
- Обязательны действующая сессия администратора и CSRF. PHP GD безопасно перекодирует изображение, удаляет EXIF, сохраняет байты только в MySQL, статус `draft`. Нет публичного API/SEO изображений.
- Если GD отсутствует, API отвечает ошибкой; **не обходить** проверку загрузкой в публичный каталог.

## Порядок установки и проверки

1. Сохранить локальные изменяемые файлы и текущий `api/admin/directory/media/upload.php` с хостинга.
2. Применить локальный ZIP v0.4b.2 в `E:\Project\native-places`; собрать `npm --prefix admin run build`.
3. На хостинге заменить **только** `/www/native-places.ru/api/admin/directory/media/upload.php` из HOST ZIP, затем загрузить содержимое `admin/dist` в действующий `/www/native-places.ru/admin/`. Не создавать физическую `/admin/directory/` (раньше вызывала 301/403).
4. Админка → «Виды рыб» → «Окунь речной» → «Загрузить изображение» → выбрать «Иллюстрация, созданная ИИ». Выбрать **действительно сгенерированный** файл, инструмент «ChatGPT (OpenAI)», подпись «Иллюстрация речного окуня, создана ИИ»; подтвердить разрешение и сохранить.
5. Проверить, что фото отображается после F5 как черновик с пометкой ИИ, без публичной ссылки, и нет HTTP 500 или ошибки PHP GD. Отдельно убедиться, что старые поля обязательны при выборе «Фотография».

**Откат:** восстановить предыдущие `SpeciesEditor.jsx` и `speciesModel.js`, снова собрать админку, восстановить предыдущий `media/upload.php`. Схему БД откатывать не нужно. Уже загруженные изображения остаются в БД, не удалять их без необходимости.

## Подтверждённые результаты до установки

- Node-тесты на валидацию происхождения и контракт PHP должны проходить при локальной сборке патча.
- PHP-синтаксис проверяется командой `php -l`.
- Реальная загрузка на хостинге и обработка GD должны проверяться отдельно; эти тесты не считаются пройденными до ответа сервера.
