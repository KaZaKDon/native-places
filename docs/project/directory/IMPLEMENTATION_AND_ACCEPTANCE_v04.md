# Native Places — v0.4: этапы, миграции и критерии приёмки

**Дата:** 16.11.2026. **Это план, не отчёт о выполненном коде.** v0.3 работает; v0.4 пока документируется.

## v0.4a — реки и именованные участки (первая разработка)

1. Снять резервные копии: БД, PHP API, публичные SEO-файлы; сравнить `SHOW CREATE TABLE directory_entries`, `directory_entry_events` и актуальный API на хостинге с `docs/backend`.
2. Создать миграцию **только** `directory_sources` и `directory_segments`, без изменения `places`, `payments`, существующего Дона и его GeoJSON.
3. Добавить в админку «Участки рек» — выбор реки, таблица участков, форма, загрузка геометрии, карта-preview, источник, черновик.
4. Сначала тест: создать черновик участка Дона → F5 → редактировать → проверить в БД; публичный API не видит черновик.
5. Для публикации участка ввести проверку родителя, содержания и геоданных. Без разметки подтверждённых границ не создавать «готовые» участки автоматически.
6. Лишь затем делать публичный блок участков и, если контента хватает, маршрут и SEO.

Приёмка: целостность FK, запрет привязать сегмент к не-реке, уникальный slug в одной реке, сохранение GeoJSON после F5, наличие подтверждённого источника, черновики скрыты, снятие родителя скрывает всех детей, родительская линия не повреждена.

## v0.4b — виды рыб и фотографии

1. Таблицы видов/подтверждённых связей/медиа; безопасная загрузка изображений.
2. Единая карточка рыбы: фото с авторством, русское/научное название, сведения и источники.
3. Отдельная связь «вид есть в Дону» и **отдельно** «вид подтверждён на участке X»; не делать массового наследования по умолчанию.
4. Проверка лицензий: файл без автора или права на использование не публикуется.
5. SEO-страницы видов — только когда есть достаточно собственной полезной информации.

Приёмка: один вид не дублируется на разных реках; права на фото видимы; нет ложных геометок для редких видов; удаление связи не удаляет биологический вид.

## v0.4c — охраняемые территории

1. Новый тип `protected_area` согласованно во фронтенде, PHP, валидации GeoJSON, карте, SEO, админке и тестах.
2. Новая таблица правового режима `directory_protection`, с источниками границ/правил и датой сверки.
3. Фиолетовый полигон только для проверенных границ; без полигона допускается содержательная карточка.
4. Посещение и запреты — отдельный блок, связанный с документами; цвет не означает автоматический запрет входа.

Приёмка: ООПТ не путается с угодьями, старые 6 категорий не меняются, переключатели слоёв работают, нет неподтверждённых границ или правовых утверждений.

## v0.4d — связи и масштабирование

1. Проверить реальные `places`/статусы/платёжную модель; добавить только безопасные связи с объявлениями.
2. Добавить фильтры карты, bbox/zoom и ограничение масштаба выдачи вместо загрузки всех геометрий.
3. Обновить индексацию после публикации содержательных страниц; canonical, Sitemap, 404 для черновиков и редиректы.
4. Проверить возврат к v0.3 при отказе до необратимых миграций.

## Обязательный шаблон каждого ZIP-патча

- `SOURCE`: **только изменённые** React/стили/тесты + `docs/project/directory/*` + `docs/backend` текстовые API-копии.
- `HOST`: **только изменённые** PHP/SQL, не весь сервер.
- `README_INSTALL`: конкретные пути, резервная копия, порядок команд и установки, тесты после каждого шага, условия отката.
- `HANDOFF.md`: версии, что уже проверено на хостинге, что только запланировано, обнаруженные ограничения, следующая команда.

Поскольку пользователь работает по одной проверке, **не** объединять выполнение миграции, загрузку PHP и React в одно поручение. Сначала локальная сборка, затем backup/SQL, API без авторизации, админка, публикация, публичный API, карта, SEO/Sitemap.
