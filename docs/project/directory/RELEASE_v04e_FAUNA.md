# Native Places v0.4e — животные территорий и правила охоты

**Подготовлено 20.11.2026. Локальный патч, на хост не установлен.** Требуется действующая v0.4d: таблица `directory_territory_details`, серверный SEO-роутер и опубликованный справочник. В архиве два дерева, `SOURCE` (локальный проект) и `HOST` (PHP на хосте). Никакой SQL в этом выпуске нет: существующие `directory_species`, `directory_species_occurrences` и `directory_territory_details` используются без изменения схемы.

## Что сделано

- В разделах **Природные территории** и **Охотничьи угодья** в админке появилась вкладка «Животные и птицы». Вид создаётся один раз в общей таблице; у птиц (`bird`) и млекопитающих (`mammal`) факт присутствия привязывается только к `protected_area` или `hunting_ground`, со своим источником и датой проверки. Рыба (`fish`) остаётся только в реке и водоёме. Растения пока не публикуются.
- Публикация вида проверяет опубликованную территорию, каждую привязку, допустимый вид источника, текст и права на изображение. Видимые API, SEO HTML и Sitemap показывают только опубликованные виды с опубликованными фактами. Сведения из неопубликованных участков, служебные заметки и черновики не раскрываются.
- В публичной карточке территории и в исходном HTML отдельно показаны блок «Животные и птицы» и правовой режим. В карточке заповедника указывается общий запрет любительской и промысловой охоты; конкретное положение и правила посещения связываются с источниками. Заказник не получает автоматический запрет: его режим индивидуален.
- Для охотугодья редактор указывает **сроки по видам, год, регион и ограничения** в существующем поле `access_rules`, обязательно с официальной ссылкой `access_source_url` и датой `checked_at`. Сервер уже блокирует публикацию непустых правил без ссылки и даты. Если данные отсутствуют, карточка так и говорит. Статус «охота открыта сегодня» не вычисляется; карточка не является разрешением на охоту. Для повторяющихся сезонов текст и дату проверки обновлять вручную перед каждым сезоном.
- Ни один животный вид, срок охоты или факт обитания автоматически не добавлен. Имеющиеся карточки Дона и окуня остаются прежними.

## Установка, по одному шагу

1. Сохранить копии действующих PHP-файлов, каталога `admin` и публичного `assets`, а также экспорт БД. Убедиться, что v0.4d установлен полностью; этот патч требует v0.4d API и SEO, но миграции v0.4e не требует.
2. Наложить `SOURCE/` на корень локального проекта `E:\Project\native-places\`. Выполнить `node --test`, `npm run build` и `npm --prefix admin run build` (если node_modules удалены — сначала `npm ci` и `npm --prefix admin ci`). Проверить PHP из `SOURCE/docs/backend/v04e/` командой `php -l` для каждого файла.
3. После локальной проверки перенести PHP из `HOST/` в `/www/native-places.ru/` с сохранением путей, а собранные `dist` и `admin/dist` разложить так же, как в v0.4d. Внутрь публичного `/admin/directory/` PHP не копировать. Сначала включать PHP, затем собранный интерфейс: старый интерфейс совместим с новым API. **Старый PHP не сможет публиковать новые виды животных.**
4. Проверить HTTP 200 и прежние данные Дона и окуня; опубликованную страницу территории, старые правила и заголовки SSR. Создать черновик птицы или млекопитающего, добавить источник, привязку к **опубликованной** территории и иллюстрацию с подтверждёнными правами. Опубликовать и проверить: карточку вида, ссылку со страницы территории, Sitemap; проверить 404 у черновика. В охотугодье заполнить официальные сроки по виду/году и проверить, что ссылка и дата выводятся.

## Проверка и пределы

- В окружении подготовки `node --test` завершился успешно (97 тестов). PHP и npm-пакетов для сборки здесь нет; `php -l` и обе сборки нужны локально до загрузки на хост. Публичное выполнение PHP с реальной MySQL не проверено.
- Сезоны пока хранятся редакционным текстом по конкретному угодью, с источником и датой, **без отдельного календаря или расчёта действующего разрешения**. Если понадобится фильтрация по виду, региону и году, потребуется отдельная модель сезонов с собственной проверкой актуальности.
- Для отката вернуть резервные копии PHP и обеих сборок. При опубликованных видах птиц/млекопитающих перед откатом снять их с публикации; старый SEO-код их не покажет. База не изменялась этим выпуском.
