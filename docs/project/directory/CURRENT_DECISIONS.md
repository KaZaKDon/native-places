## Открытые решения

1. Финальная нумерация следующей итерации: ранний документ называл v0.4c разработкой ООПТ; после успешной v0.4b.2 ближайшая задача — публикация видов/участков. Присвоить им номера **перед патчем**, не смешивать содержимое.
2. Схема и формат URL отдельных публичных страниц участков, видов, ООПТ; SEO-условия до запуска.
3. Источник и юридический режим конкретных заповедников/угодий, точность геометрии, период обновления.
4. Политика публикации личных наблюдений: показывать приблизительный период и область, избегать лишней персональной информации/секретных точек.
5. Медиахранилище при росте нагрузки: сейчас приватные `MEDIUMBLOB` в MySQL; возможен перенос вне docroot.

**Контроль:** решения не означают, что соответствующая функция работает в production. Реализация и тесты — только в `MASTER_PLAN_AND_STATUS.md` и `VERIFICATION_*.md`.


## 17.11.2026 — правила публикации видов (v0.4c, пока код)

- Виды рыб становятся публичными только после отдельного подтверждённого действия администратора, не при сохранении формы.
- Для публикации нужны содержательная карточка, минимум один источник факта присутствия на опубликованном водоёме, изображение с указанием происхождения/прав. Снятие с публикации блокирует публичные изображения и факты.
- Личное наблюдение, книга, научная работа и официальный источник не рассматриваются как магическая гарантия нынешнего присутствия вида. Указываем природу, место и период данных без ложной категоричности. Дата «сверено» не равна дате ловли.
- Если именованный участок ещё черновик, его название/геометрия не публикуются через карточку вида; информация о факте может быть показана на уровне опубликованной реки, без раскрытия неопубликованных деталей и личных примечаний.
- URL источников необязателен без исключений. Обязательны понятные реквизиты и provenance изображений (фотография либо ИИ-иллюстрация).
- Статусы: **v0.4b.2 на хосте подтверждён**, **v0.4c только подготовлена**. Публичные участки, заповедники/ООПТ, охотугодья и другие природные данные остаются в roadmap.
