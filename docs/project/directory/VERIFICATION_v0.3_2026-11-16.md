# Native Places — подтверждение установки v0.3

Дата проверки: 2026-11-16.

## Подтверждено на опубликованном сайте

- Локальные сборки публичного сайта и админки v0.3 прошли без ошибок (со слов пользователя).
- Публичные API: `GET /api/directory/index.php` первоначально возвращал пустой список, пока Дон оставался черновиком; `GET /api/directory/show.php?type=river&slug=don` возвращал 404 до публикации и 200 с данными после неё.
- В админке объект «Дон» опубликован, URL `/directory/river/don`.
- Страница `/directory` и страница `/directory/river/don` открываются. Карточка Дона отображает описание и картографическую линию.
- В `sitemap.xml` присутствуют `/directory` и `/directory/river/don` после публикации.
- На общей карте слои «Объявления» и «Справочник» переключаются независимо. Синий контур участка Дона скрывается и появляется при переключении слоя «Справочник».
- Нажатие на линию Дона открывает всплывающую карточку с названием, типом и ссылкой «Открыть справочник».
- Главная страница показывает три центрированные кнопки: «Исследовать карту» (золотая), «Категории» (тёмная), «Справочник» (золотая). Обе золотые кнопки одинакового размера. В первой текст занимает две строки по длине названия.
- После исправления серверной маршрутизации ранее проверена работа F5 в `/admin/directory`.

## Данные первой записи

- Река Дон, регион Ростовская область, тип `river`, slug `don`.
- Геометрия: `MultiLineString` из 4 линий и 117 координат, источник OpenStreetMap; видна в карточке и на общей карте.
- Справочная информация бесплатная; объявления остаются самостоятельной платной моделью в шести существующих категориях.
- В публичном API и Sitemap должны отображаться только опубликованные записи; в ходе внедрения поведение для черновика Дона проверено.

## Архитектурные условия для следующих этапов

- Действующий PHP API находится на хостинге. В локальном проекте `docs/backend` лежат текстовые копии серверных файлов: перед патчами сверять их с фактическими файлами сервера.
- Патчи для локальных исходников и хостинга готовить раздельно. Не переписывать существующие API, объявления и платежи без необходимости.
- Каждый этап сопровождать обновлением документации в `docs/project/directory/` и файла передачи контекста (`HANDOFF.md`) после сверки его текущего содержания.
