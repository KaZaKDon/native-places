# Native Places v0.4b — безопасная установка, проверка и откат

**Пока не запускалось на хостинге.** Проводим **по одному шагу** после подтверждения каждого.

## Этап A — локально

1. Резервная копия `E:\Project\native-places`. Распаковать **SOURCE ZIP в корень** с сохранением относительных путей.
2. В PowerShell `npm --prefix admin run build`. В конце — `✓ built ...`, код выхода `0`. Никаких файлов в root `/admin/directory` на хосте не создавать.
3. На этом шаге не загружать `dist` на хост и не запускать SQL.

## Этап B — хостинг / база

1. Сохранить полный SQL-бэкап именно `vnuko1796_nativeplaces_dev` (при совпадении актуального имени базы) и резервные копии `api/admin/directory` и каталога `admin`.
2. В phpMyAdmin проверить `SHOW TABLES LIKE 'directory_%';`: **до миграции** должны быть `directory_entries`, `directory_entry_events`, `directory_sources`, `directory_segments`. Если появились имена будущих таблиц — НЕ запускать миграцию повторно без сверки схемы.
3. Проверить `directory_entries.id`, `directory_segments.id`, `directory_sources.id` — типы `BIGINT UNSIGNED`, движок InnoDB. SQL v0.4b рассчитан на MariaDB 10.5 / PHP 8.x, но без staging-базы совместимость остаётся неподтверждённой.
4. Импортировать **один файл** `db/migrations/20261116_directory_species_media_v04b.sql` из HOST ZIP через вкладку «Импорт». Ожидается 4 SQL-команды `CREATE TABLE IF NOT EXISTS`, ни одной `ALTER` старых таблиц.
5. Проверить `SHOW TABLES LIKE 'directory_%';`: должно стать 8 таблиц. После этого сделать снимок новой схемы.

## Этап C — PHP

1. Загрузить **только новые файлы** под `/www/native-places.ru/api/admin/directory/`: три папки `species`, `occurrences`, `media`. НЕЛЬЗЯ класть PHP в физический `/www/native-places.ru/admin/directory/` — ранее именно эта ошибка вызывала 301/403 для React-маршрута.
2. Проверить по очереди GET URL `https://native-places.ru/api/admin/directory/species/index.php`, `.../occurrences/index.php?species_id=1`, `.../media/index.php?species_id=1`. Без сессии каждый возвращает `401` JSON. Сначала убедиться, что работает основной API.
3. В PHP проверить наличие GD **без раскрытия конфигурации публично**. Если GD отсутствует, все функции видов и связей работают, но загрузка фото отдаст 503 JSON: потребуются настройка хостинга или безопасная переработка механизма.

## Этап D — админка

1. Сохранить копию текущего `/admin` (только существующей сборки, **не** создавать каталог `/admin/directory/`).
2. Загрузить содержимое локального `admin/dist` в действующую папку админки.
3. Проверить `https://native-places.ru/admin/directory`, F5 → HTTP 200; вкладку «Виды рыб», загрузку видов после входа.
4. Создать один **черновик** вида, обновить страницу, проверить сохранение. Затем привязать к Дону *только при наличии подходящего источника*, необязательный конкретный участок выбирать лишь при доказательствах.
5. Добавить собственное или разрешённое фото, проверить превью и его недоступность без авторизации. При ошибке остановиться и прислать ответ API, ничего не публиковать.
6. После установки дополнить `HANDOFF.md` датой и фактическими проверками, не выдавать подготовленный код за установленный.

## Откат

- При ошибке сборки — вернуть локальные изменённые файлы; хост ещё не затронут.
- При проблеме с API — вернуть старую админку и временно убрать **только новые** каталоги PHP `species`,`occurrences`,`media` из `/api/admin/directory`; старую базу Дона и действующие `directory_entries` не менять.
- Новые четыре таблицы не удалять автоматически: там уже могут быть черновики. Откат БД — только из сохранённого полного бэкапа и после отдельного решения; не выполнять `DROP TABLE` в production без проверки.
