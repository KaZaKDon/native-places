# Native Places v0.4d — охотничьи угодья и ООПТ

**Подготовлено 19.11.2026. На хосте не установлено.** Предыдущий v0.4c.1 подтверждён: страница окуня отвечает HTTP 200 и входит в Sitemap.

## Объём

- Тип `protected_area` добавлен синхронно в PHP, админку, React, серверный SEO и карту. Отдельный фиолетовый цвет задаётся централизованным токеном.
- Охотугодья остаются своим типом `hunting_ground`; для обоих типов вводится таблица `directory_territory_details`: официальная категория/название, орган управления, правовой документ, источник точных границ, проверенный режим посещения с источником и датой.
- Публикация территории требует официального названия и ссылки на правовой документ. Геометрия может отсутствовать; если есть, публикация требует ссылку на **официальный источник точных границ**. Режим нельзя публиковать без отдельного источника и даты проверки.
- Публичные карточки, SEO HTML и карта используют только опубликованные записи. Платные объявления и таблица `places` не меняются.
- Две заготовки с проверенными базовыми сведениями подготовлены в `OOPT_DRAFT_CARDS_v04d.md`: заповедник «Ростовский» и заказник «Цимлянский». Это **не заповедники одного типа**. Без официальных векторных границ геометрия пуста, обе записи не добавляются в БД автоматически и не публикуются без редакторской проверки.

## Порядок установки

1. Сохранить БД и текущие серверные PHP. Сравнить серверные файлы `api/admin/directory/{_bootstrap,index,save,publication}.php`, `api/directory/{_bootstrap,show}.php`, `seo-router.php` и `seo/directory.php` с файлами HOST ZIP. Текущая папка API на хосте в доступном нам архиве отсутствовала, поэтому слепая замена PHP **не проверена**. При расхождении PHP перенести изменения в актуальные файлы, а не затирать новые функции хоста.
2. Применить миграцию `docs/backend/migrations/20261119_directory_territory_v04d.sql` к целевой БД ровно один раз. Она создаёт только новую таблицу.
3. Перенести PHP из HOST ZIP с сохранением структуры путей; проверить синтаксис `php -l` каждого затронутого файла до переключения сайта. Обновить собранные фронтенд и админку из локального SOURCE ZIP командой `npm ci && npm run build` и `npm --prefix admin ci && npm --prefix admin run build`, затем переносить их обычным способом. В архивах готовых `dist` нет.
4. Проверить: старый Дон и окунь отвечают 200; `/api/directory/index.php` и `/api/directory/map.php` возвращают JSON; новая неопубликованная запись `protected_area` даёт 404 на публичном URL; после создания и публикации проверенного объекта — 200, canonical, исходный HTML, Sitemap, карта. Пустая геометрия не рисует контур. Попытка публикации полигона без `boundary_source_url` даёт 422.

## Откат

Вернуть резервные копии PHP и фронтенда. Таблицу `directory_territory_details` оставить до отдельной миграции отката; удаление таблицы уничтожит новые черновики. Новые ООПТ перед откатом снять с публикации, иначе старый код не поймёт тип. До установки SQL новый PHP не включать: `LEFT JOIN` нужен всем карточкам справочника.
