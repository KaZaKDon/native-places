# Native Places — v0.4c.1: исправление серверного SEO видов рыб

Дата: 18.11.2026.

## Обнаруженный дефект

В **самом ранее подготовленном** HOST ZIP v0.4c забыты подключения `seo/species.php` и обработчик маршрута `/directory/species/{slug}` в `seo-router.php`, а в `sitemap.php` отсутствует выборка опубликованных видов. Поэтому даже после успешной публикации вида через API SEO-страница отвечала 404. Это не ошибка пользователя при установке и не неисправность MySQL.

## Что изменено

- `seo-router.php`: подключён `seo/species.php`; отдельный `/directory/species/{slug}` обрабатывается **раньше** универсального `/directory/{type}/{slug}`; при неопубликованном виде — 404, при опубликованном — 200 с мета-тегами, canonical, BreadcrumbList, Schema.org Taxon и HTML-контентом. При ошибке БД — 503 с noindex.
- `seo-router.php`: на опубликованной странице Дона добавлен серверный HTML-блок со ссылками на опубликованные виды, без раскрытия черновых названий участков. Ошибка выборки рыб не превращает страницу Дона в 503.
- `sitemap.php`: отбор только `published` рыб с опубликованным подтверждением. Генерирует canonical URL и изображение только если изображение опубликовано; черновики не индексируются.
- `tests/directory-species-seo-hotfix.test.js`: регрессионные проверки присутствия маршрута, приоритета перед общей маской, фильтрации, карты сайта и отсутствия изменений API/платных объявлений.

**Новых миграций, изменений админки или публичного React нет.** API уже подтвердил 200, опубликованный Дон — 200, HTML рыбы — пока 404 до установки исправления.

## Порядок установки

1. **На хостинге** сохранить копии двух текущих файлов в корне `/www/native-places.ru/`: `seo-router.php`, `sitemap.php`.
2. Заменить ровно эти два файла файлами HOST ZIP v0.4c.1. Не создавать каталоги `/admin/directory/`.
3. Проверять по одной команде: `curl.exe -sS -o NUL -w "HTTP %{http_code}\n" https://native-places.ru/directory/species/okun-rechnoy` — ожидается 200.
4. Далее проверить title/canonical/H1, URL Дона (200), строку `/directory/species/okun-rechnoy` в Sitemap и публикационные ограничения на черновик. Проверять доступность картинки. Только после этого отмечать исправление как установленное и проверенное.
5. SOURCE ZIP распаковать в локальный `E:\Project\native-places` с заменой тех же двух текстовых файлов, добавлением теста и обновлением документов. API на хосте, локальные PHP — только документация; в SOURCE ZIP нет новых бинарных сборок.

## Откат

Вернуть обе резервные копии `seo-router.php` и `sitemap.php` с хостинга. База и API не менялись. При откате рыбный SEO-URL снова будет 404. Не удалять опубликованного окуня, не запускать SQL повторно.

## Статус проверки

- Проверено до исправления: `HTTP 200` у публичного API вида; `HTTP 404` у SEO-URL; Дон `HTTP 200`.
- Проверено локально для v0.4c.1: PHP `php -l` для `seo-router.php` и `sitemap.php` — PASS; 5/5 регрессионных тестов Node — PASS. Production без установки пока не проверен.
- **Не проверено в production**: исправление на хостинге, SEO 200, Sitemap после исправления.
