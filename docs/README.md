# Документация Native Places

Папка `docs` разделяет фактическое состояние системы, юридические требования и планы развития.

## Разделы

```text
docs/backend/   точные копии PHP backend с хоста и индексные документы
docs/legal/     юридическая база и описание продукта
docs/project/   состояние проекта, архитектура, планы, backlog и данные
```

До завершения инвентаризации в архиве могут сохраняться старые рабочие папки. Они не имеют приоритета над `docs/backend` и `docs/legal`.

## Приоритет источников

При расхождении сведений используется следующий порядок:

1. Код в `docs/backend/**` — фактический backend на хосте.
2. Код в `src/**` — фактический публичный frontend.
3. Код в `admin/src/**` — фактическая админка.
4. `docs/legal/**` — актуальные юридические требования до проверки юристом.
5. `docs/project/**` — планы и описания, которые должны обновляться после изменения кода.

## Как фиксировать изменение backend

Для endpoint `api/example/action.php` используется документ:

```text
docs/backend/example/action.php.md
```

После изменения PHP на хосте в документе обновляются код, контракт, дата проверки и история изменений. До пункта 7.3 текущей инвентаризации endpoint-документы не редактируются массово.

## Юридические документы

Юридический текст и его техническая реализация — разные слои:

- содержание и статус редакции хранятся в `docs/legal`;
- публичные URL, версии, принятие согласий и журнал событий реализуются сайтом и backend;
- внутренняя редакция или платная оферта со статусом `draft` не должна автоматически становиться публичной.

## Актуальный статус

- `docs/project/CURRENT_STATE.md` — что существует сейчас;
- `docs/project/ROADMAP.md` — что и в каком порядке изменяется.
