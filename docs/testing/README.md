# Тестирование Native Places

Тесты находятся только в исходном проекте и не загружаются в production.

## Структура

```text
src/**/*.test.js       — быстрые модульные тесты
tests/e2e              — локальные браузерные сценарии
tests/admin            — локальные сценарии административной панели
tests/helpers          — API-заглушки для локальных сценариев
tests/smoke            — read-only проверки https://native-places.ru
```

`playwright-report` и `test-results` создаются локально и исключены из Git.

## Первичная установка

После получения проекта выполнить:

```powershell
npm install
npm --prefix admin install
npx playwright install chromium
```

Браузер Chromium устанавливается один раз на каждом рабочем компьютере.

## Команды

Быстрые модульные тесты:

```powershell
npm test
```

Локальные браузерные тесты. Команда сама создаёт production-сборку, запускает
локальный preview и подменяет обращения к API безопасными ответами:

```powershell
npm run test:e2e
```

Интерактивный режим Playwright:

```powershell
npm run test:e2e:ui
```

Локальные браузерные тесты админки с безопасными API-заглушками:

```powershell
npm run test:admin
```

Полная проверка перед загрузкой на хост:

```powershell
npm run check
```

Безопасная проверка уже опубликованного сайта:

```powershell
npm run test:production
```

Только безопасные проверки production API:

```powershell
npm run test:production:api
```

Production smoke выполняет только GET-запросы. Он проверяет серверное SEO,
отрисованный браузером SEO, публичные справочники и каталог, карточку объявления,
отзывы, гостевую сессию и защиту личных API-разделов. Он не регистрирует
пользователей, не создаёт объявления, не отправляет сообщения и не меняет данные.

Кратковременные сетевые сбои повторяются внутри каждого production-запроса до
двух раз. Поэтому единичный `socket hang up`, успешно прошедший после повтора,
не считается неисправностью сайта.

## Когда запускать

1. После небольших изменений — `npm test`.
2. После изменений админки — `npm run test:admin`.
3. Перед каждой загрузкой на хост — `npm run check`.
4. После загрузки на хост — `npm run test:production`.
5. Если код не менялся, ежедневный ручной запуск не требуется.

## Правило безопасности

Будущие сценарии регистрации, объявления, сообщений, отзывов и модерации нельзя
направлять в рабочую базу. Для них потребуется отдельный тестовый backend и БД,
например `nativeplaces_test`. До создания такого окружения E2E остаются
неизменяющими данные.
